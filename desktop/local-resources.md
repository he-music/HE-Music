# 本地播放资源

mygo 的扫描条目 `ScanEntry.path` 保存绝对路径，`relativePath` 和 `ref` 继续用于现有目录扫描、标签编辑及文件操作。多个音乐目录中的同名文件通过各自绝对路径定位。新下载文件在正式扫描结束前的即时入库条目也带绝对路径。

- 本地音频：`<gateway>/__local/audio?path=<绝对路径>`，Go 每个 HTTP 请求打开文件并流式返回，支持 GET、HEAD、Range／206／416，不创建单曲票据、不启动独立音频服务。
- 在线音频：继续使用现有 HTTP 网关，包括在线音频解密。
- 本地封面：`<gateway>/__local/artwork?path=<绝对路径>`，直接作为图片 URL。
- 本地歌词：`<gateway>/__local/lyrics?path=<绝对路径>`，返回 UTF-8 文本，由原歌词解析器处理。

`gateway` 是应用启动时已有的 loopback 地址，包含其原有会话前缀。本地资源路由直接读取路径，不需要单曲票据或文件引用注册；不调用远程 transport。GET 和 HEAD 均可用，缺少资源返回 404。前端添加页面及扫描条目代次参数，让浏览器复用封面和歌词的 HTTP 缓存；重新扫描或重载页面会刷新同名封面和歌词。图片请求失败时沿用组件占位内容。

封面优先内嵌正面图，再尝试其他内嵌图片；没有可用图片时查找音频同名的 `.jpg`、`.jpeg`、`.png`、`.webp`、`.gif`（含大写后缀）。HTTP MIME 从图片字节识别，支持 JPEG、PNG、GIF、WebP；不再按标签 MIME 或 4096px 边长过滤。单张封面限制 8 MiB，标签解析累计读取预算 16 MiB。

歌词优先同名 UTF-8 `.lrc`，然后内嵌 Lyrics；文本限制 1 MiB。标签编辑器仍使用完整 metadata 读写事务，保存前由播放器清空本地音源并阻止未决本地播放，在线音源不受此操作影响。

## 实机验证

macOS 实测直接 file URL 返回 `NotSupportedError` 后，浏览器本地音频统一切到 HTTP 网关。仍需分别在 macOS、Windows、Linux 的实际 mygo WebView 中验证播放；HTTP 与静态编译测试不代表真实解码及发声验收。

1. 配置两个音乐目录，分别播放其中同名的歌曲。
2. 验证开始播放、时长、暂停／恢复、seek、切歌，以及中文／空格／`#`／`%` 文件名。
3. Windows 另测盘符路径和可访问的 UNC 共享路径。
4. 验证内嵌和同名封面、同名 LRC／内嵌歌词；替换 sidecar 后重新扫描。
5. 播放本地歌曲时保存标签，确认清空音源，重新选择后可以播放；切换到在线歌曲后播放仍正常。

浏览器不再尝试 `file://`，音频、封面和歌词共用现有本地网关。音频设置正确的容器 MIME，FLAC 沿用 Safari 的 `<source type="audio/flac">` 提示；本机网关已经返回 CORS 响应，因此跳过额外的 Range CORS 探测。未来接入 mpv 时仍可使用扫描条目的原始绝对路径，封面和歌词继续由应用展示。
