# mygo 桌面端迁移方案

状态：基础迁移候选及 macOS 开发合成验证已交付，按用户最新授权继续迁移剩余桌面功能。Windows 运行测试延后到功能迁移完成后，届时统一交付测试清单；不作为当前开发阻断。

## 已明确的目标

- 迁移方向为使用 mygo 替代 Electron 桌面框架。
- Web 端继续支持独立构建和部署。
- 优先复用现有 Vue 前端，并考虑使用 Go 维护桌面能力，降低长期维护门槛。
- 接受在迁移过程中定位 mygo 问题，整理最小复现并向上游反馈。
- 在独立分支 `feat/mygo-migration` 中推进。

## 文档与任务组织

- 本文记录迁移范围、待决策问题、实施任务、依赖与验收证据，作为持续维护的迁移计划。
- 通过逐轮设计访谈明确选择；已确定的问题及时记录，不将建议视为已确认要求。
- 涉及重要且长期有效的架构取舍时，再在 `docs/adr/` 中记录原因。
- `CONTEXT.md` 仅维护产品术语，不保存迁移任务或技术实现决策。

## 已核实的技术事实

能力核对基于 mygo 上游提交 `07ebe19ac0dc512909a8c4e73f66e6e8428283a6`；实现前需要选择并验证实际使用版本。

- mygo 支持现有 Web 技术栈、前端资源嵌入，以及 Go 服务绑定、类型化事件和 Channel。
- 已提供窗口、托盘、全局快捷键、多屏信息、窗口状态保存、防休眠、系统媒体控制和签名自动更新等能力。
- 当前 Linux 窗口实现的 `SetIgnoreMouseEvents` 是空函数；公开接口也未提供 Electron 的鼠标事件 `forward` 参数。
- 官方文档指出 Linux WebKitGTK 无法通过自定义协议播放音视频，建议使用本地 HTTP 服务提供媒体。
- 官方 Fetch 插件可由 Go 发起 HTTP 请求，但 Cookie 与 WebView 分离，需要适配当前请求逻辑。
- Go 原生音频模块不能直接视为现有 Web 播放器的完整替代；是否更换播放引擎尚未决定。
- 当前项目包含 Fastify、网易接口、解灰、登录回调和播放控制服务；需要核对其实际使用情况再决定保留或迁移方式。

## 已确认的首阶段范围

- 桌面验收平台为 Windows 和 macOS；Linux 不作为首阶段必须通过的验收平台。
- 本机仅调试 macOS；Windows 的运行与交互由用户自行测试，代理保留可执行的验证清单并记录尚未验证项。
- 执行过程保存在 `docs/plans/mygo-migration-log.md`，包含阶段交接、验证命令、失败及修复记录；敏感信息不写入记录。
- 首个里程碑为基础可用版：保留 Web 独立构建，打通登录、在线听歌和播放器内歌词。
- 首版桌面应用即不携带 Node 运行时，不采用 Node 子进程作为过渡方案；前端构建工具仍可使用 Node。

## 调用链核对

- 主要页面和在线歌曲地址已通过 `requestHemusic` 调用独立 HE-Music 后端。
- 代码中仍有旧版网易接口调用；需要追踪实际入口，不能仅按接口文件是否存在判断其是否需要迁移。
- 第三方登录当前使用本地 `/login/success` 回调并通过 Electron 事件通知前端；首阶段需要替换这条链路。
- 全局初始化当前会调用快捷键、桌面歌词、自动更新和协议注册；基础可用版也需要避免调用尚未接入的桌面能力。

## 已确认的服务与登录边界

- 首版仅使用现有 HE-Music 后端；旧网易或解灰入口允许暂时移除。
- 不要求将旧网易和解灰服务整体移植到 Go，也不为首版新增独立的旧接口服务。
- 密码、扫码和后端提供的第三方授权方式全部纳入首阶段验收。
- 第三方授权当前依赖的本地回调链路需要用 Go/mygo 替代。
- 对仍在活动调用链中的旧接口，先核对业务用途和现有 HE-Music 后端覆盖情况，再移除或改接；不可仅删除整个接口文件。

## 实施任务草案

以下任务已获实施授权；按依赖分阶段执行，并在执行日志中更新实际结果。

- M0：核对运行依赖与接口调用，确认 mygo 版本和构建工具链。验收：明确实际依赖的接口、旧接口处理清单与待验证平台差异。
- M1（依赖 M0）：拆出独立 Web 构建并建立 mygo 应用入口。验收：Web 可独立部署，桌面可加载共享 Vue 页面，桌面产物不携带 Node。
- M2（依赖 M1）：建立 Web 与 mygo 平台适配并处理应用初始化。验收：共享业务通过平台能力访问桌面，未接入能力不阻断启动。
- M3（依赖 M2）：接通首阶段登录和网络请求。验收：密码、扫码、第三方授权、鉴权请求与令牌刷新可用。
- M4（依赖 M3）：接通在线播放与播放器内歌词。验收：播放、暂停、切歌、进度跳转和现有歌词效果按约定通过验证。
- M5（依赖 M4）：完成首阶段构建和真实界面验收。验收：Web、Windows 和 macOS 分别记录构建、播放及交互验证证据。

扩展桌面功能按文末顺序继续实施，每一阶段分别保留交接、验证和独立审查。

## 本机候选与人工验收

当前 macOS arm64 候选：`build/mygo/darwin-arm64/HE-Music.app`，主程序 17,841,968 字节，
SHA256 `850712948232fb725c8ac26595e5d4cacfcbe06284240943040e7c680128af5f`。
该包为工作区 ad hoc 签名构建，没有公证，不是正式发布产物；无需 Node 即可运行。
本轮歌词接线未重新构建候选，上列哈希不代表包含本轮改动的产物。

```sh
# 从仓库根目录启动已构建的普通候选
open build/mygo/darwin-arm64/HE-Music.app

# 开发 mygo（现有 pnpm dev 仍为旧 Electron 开发命令）
pnpm run dev:desktop

# 重新构建普通 macOS arm64 候选；确保未设置 GOFLAGS=-tags=nativeprobe
pnpm run build:desktop:mac

# 独立 Web 构建与预览
pnpm run build:web
pnpm run preview:web
```

构建环境为 Go 1.27.3、Node 24 LTS（本机验证 24.22.1）、pnpm 10.28.1；确保 Go 的 bin 在
PATH 首位。原生探针运行期间不要执行构建、绑定生成或源码写入，避免 Vite 整页刷新污染证据。
探针专用开关不可用于普通人工验收。Web 独立产物位于 `dist/web`，mygo 前端位于 `dist/desktop`。

以下为功能迁移完成后的人工验收顺序；当前先继续开发，暂不要求执行 Windows 测试。验收时不需要向代理发送密码、令牌、Cookie 或回调参数：

1. 分别验证密码登录、扫码确认、后端动态列出的每个第三方 provider；测试取消、重新登录、刷新与登出。合成回调没有验证真实后端 redirect、expires_at 单位和登录后的业务结果。
2. 登录后选一首真实歌曲，确认实际可闻声音、播放/暂停、前后切歌、暂停中和播放中跳转、快速切歌；遇策略拒绝时当前曲目保留，再次点击可恢复。
3. 分别切普通、AMLL、Monet，检查普通与逐字歌词、高亮/偏移/歌词点击跳转、半屏歌词布局和纯歌词模式、缩放及隐藏恢复。AMLL 弹簧升级不纳入本轮新增修补。
4. 验证后端实际返回的 MP3、FLAC 等编码和 HTTP/HTTPS、重定向、Range、失效音源；开发静音 PCM 不能替代实际格式或打包 origin 的媒体能力。
5. Windows 在本机依照专用清单构建、检查 WebView2 并重复真实账号与媒体场景。macOS 结果不覆盖 Windows。

桌面歌词及本地MP3/FLAC扫描/票据播放代码已接通，真实新锁定、picker/音乐库、实际声音与普通包仍待验收。更新前端已接通但发布feed/key尚缺；下载、原件标签写回产品接线及实际更新验收仍未完成；系统媒体封面保留既有开发合成验证与独立审查结果。
旧网易/解灰服务不在 mygo 中恢复；旧 Electron 源码和命令继续作为迁移参照。
