# mygo 应用数据与 Electron 导入

mygo 将应用业务数据保存在 `mygo.App.Path(mygo.PathUserData)` 下的 `business-data-v1` 中。纯 Web 和 Electron 继续使用原来的 localStorage／IndexedDB。

设置、快捷键、登录状态和播放状态在挂载 Pinia 前从 Go 预载，后续通过写入队列保存。歌单、历史、下载任务和背景图片使用按数据库区分的异步接口。二进制图片在磁盘保存原始内容；目录和键名均由原生端限定或编码，业务记录不能授予音乐文件访问权限。

每条记录通过临时文件、同步和原子替换保存。读取到损坏数据时保留原文件，阻止默认值覆盖；启动读取失败会显示重试入口。正常的前端退出、重新加载和导入会等待写入队列。强制结束进程可能丢失尚未送达原生端的修改。

## 从已发布的 Electron 版迁移

1. 在旧 Electron 版打开开发者工具，在 Console 中执行仓库内的 `scripts/migration/export-electron-data.js`。
2. 保存下载的 `HE-Music_Electron_Data_*.json`。
3. 在 mygo 的「常规设置 → 备份与恢复 → 应用数据」点击「导入数据」，选择文件并确认。

导出助手只读取旧版的业务存储和原生偏好，不修改来源数据库或音乐文件。导入包含设置、快捷键、登录信息、歌单、历史及背景图片；旧桌面歌词颜色、字体、显示选项和窗口无边框偏好会转换到对应的新模型。窗口坐标及跨平台几何不导入；无边框变更仍按现有设置流程在重新启动后生效。

旧版原有的「导出设置」文件只包含设置，不包含完整业务数据，应继续使用「导入设置」。未发布的 mygo 试验版浏览器数据不做迁移。

音乐文件和目录授权不在备份中。导入后，需要在 mygo 中重新选择来源音乐目录；持久化路径、旧歌曲信息和下载历史都不能替代当前授权。更换默认下载目录仍只影响新任务，导入任务保留原目标目录。

## 导出和恢复 mygo 数据

「导出数据」生成 `he-music-application-data` 格式、版本 1 的 JSON 文件。下载历史仍经过既有字段校验，只包含安全的任务快照，不包含文件引用、授权 token 或临时 URL。

导入会替换当前业务数据并停止当前下载。原生端先验证并写出完整临时数据树，再切换整个目录；中途退出会在下次启动恢复旧目录或保留已经完成切换的新目录。切换后，旧页面的存储写入被拒绝，重新加载后的页面从新数据树预载。

只重置设置会清除设置和窗口样式，保留快捷键、账号及历史；清除全部应用数据会清除业务数据树及对应原生偏好，不删除已下载或用户选择的音乐文件。

单条数据最多 64 MiB，备份最多 128 MiB；超限操作会失败并保留原数据。

## 文件日志

mygo 日志位于 `mygo.App.Path(mygo.PathLogs)/mygo/`，按 UTC 日期分文件；活动文件达到 2 MiB 后轮转，同一天保留一个前序文件，清理超过 14 天的本功能日志。文件使用私有权限，旧 Electron 日志目录内容不受清理规则影响。

Go 标准日志继续输出到控制台，同时写入文件。主页面仅转发警告、错误的诊断字符串和未处理错误类别，不序列化账号对象、响应内容或堆栈；原控制台输出保留。落盘前处理凭据字段、带参数的 URL 和换行，前端上报按页面限量。日志失败不阻止播放器启动。
