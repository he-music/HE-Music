# 响应式布局约定

视口宽度与平台身份分别处理。`useMobile` 中的 `isDesktop`、`isTablet` 等字段只描述宽度；导航和播放器使用 `isDesktopLayout`、`isMobilePlayer`、`isMobilePlayBar` 决定交互结构。

## 布局策略

- mygo 始终保留桌面导航、底部切歌按钮和桌面全屏播放器。窗口变窄时调整界面密度，不切换为滑动分页的移动端播放器。
- mygo 的侧栏始终由用户手动展开、收起，窗口缩小不强制折叠；音质和桌面歌词入口保持直接显示。播放条在小于 1024 CSS px 时隐藏时间文字，全屏播放器通过压缩右侧留白容纳完整操作区。
- 桌面歌词使用悬浮窗图标，开启时显示选中背景，关闭时显示普通图标；通过悬停提示表达显示／隐藏操作，不使用 ON／OFF 角标。
- mygo 主窗口最小尺寸为 960 × 600 DIP；恢复旧窗口尺寸时也应用该下限。该值是本产品双栏播放器的设计下限，不代表行业通用的桌面断点。
- 封面同时受内容宽度和窗口高度约束，为长歌名、歌曲信息和上下控制区留出空间。
- 网页端继续按宽度切换布局：小于 990 px 使用移动端全屏播放器，小于 810 px 使用窄屏播放条，小于 1024 px 使用抽屉导航。

基础断点与业务阈值统一定义于 `src/constants/layout.ts`。网页导航的 1024、移动端播放器的 990 分别独立；侧栏与播放器操作入口不使用统一的 1200 阈值强制收起。歌词组件通过父级的 `compact` 布局状态收缩，避免各自判断窗口宽度后产生混合布局。

## 验证记录

使用浏览器加载真实应用组件，并分别启用 mygo 和 web 布局策略；通过临时长歌名、双语歌词数据检查布局，验证页面已移除。

- 比较 900、960、1000 × 600；核心操作均可容纳，选择 960 为双栏歌词保留更多宽度。
- mygo 在 960 × 600 下保留音质和桌面歌词的直接入口，底部播放器与全屏播放器的操作区均保持单行。侧栏可以手动展开到 240 px、收起到 64 px，缩放窗口不覆盖用户选择。
- 960 × 600 下检查六种歌词效果、封面／唱片／全屏封面以及纯歌词模式：使用桌面歌词工具栏，封面保持方形，长歌名信息未侵入底部控制区。
- 网页端检查 390、960、1000 px：手机和平板宽度使用移动端播放器，宽度增加后恢复桌面播放器。

上述几何与交互检查使用 Chromium，尚未在 macOS 原生 WKWebView 中复验。Go 检查不替代原生窗口拖动、窗口尺寸恢复和系统标题栏的实际验证。
