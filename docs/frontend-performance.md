# 前端加载与更新测量

本次优化只调整 Vite 分包，以及 AMLL 歌词、动画背景的异步加载边界。播放器的组件生命周期和播放时钟保持原有行为。

## 测量条件

- 基于 `61680b3` 及本轮启动兜底、CI 改动的工作区，对比优化前后构建。下表在后续播放器职责提取和本地匹配改动之前采集，不作为后续版本的固定体积预算。
- Node 24.22.1、pnpm 10.28.1，`vite build --config vite.config.ts --manifest`，同一台机器和本地 Vite preview。
- 每次使用新的隔离 Chromium 会话打开推荐首页，未登录、没有歌曲、未展开播放器。后端地址固定为不可用的 `http://127.0.0.1:14669`，排除真实账户和推荐内容差异。
- 等待 `.home-page` 挂载，收集 Resource Timing 中同源 `.js` 地址并去重，再读取这些响应的解压后正文长度。浏览器未提供有效的 `decodedBodySize`，因此正文大小通过 `fetch(...).arrayBuffer().byteLength` 核对。
- 大小是已请求脚本的正文总量，不是 gzip 传输量、缓存命中量或执行耗时。未以本地单次导航耗时推断用户实际加速比例。

## 结果

| 指标                   | 优化前      | 优化后      |
| ---------------------- | ----------- | ----------- |
| 首页已请求 JS 正文     | 2,360,191 B | 1,973,905 B |
| 去重后的 JS 请求数     | 53          | 55          |
| 首页加载 Pixi          | 是          | 否          |
| 首页加载 AMLL 渲染组件 | 是          | 否          |
| 首页加载视频库         | 否          | 否          |

JS 正文减少 386,286 B，约 16.4%；共享模块拆分使请求数增加 2 个。Naive UI 仍是首屏主要依赖；不为了消除大包警告而强行拆分全部组件。

分包仅匹配明确的依赖包，并启用 `onlyExplicitManualChunks`。通用依赖由 Rollup 共享，避免通用辅助代码被吸入 Pixi 等按需分包后反向带入启动链。业务 store 不再被手动强制合并为单个分包。

## 按需功能检查

在同一生产构建中，通过隔离会话设置合成歌词并展开播放器，选择 AMLL 与动画背景：

- 首次选择后才请求 `AMLyric`、`BackgroundRender` 和 Pixi，合成歌词实际出现在 `.lyric-am`。
- 继续使用现有 FullPlayer 及内部显示条件，没有通过父级开关重建整个播放器来换取加载量下降。
- 视频库保持原有路由加载边界。普通根入口未请求视频库，不将它的体积误计为首页成本。

这项检查使用程序设置和合成歌词，不代表真实音源、逐字歌词质量或操作系统音频输出验收。

## 高频状态检查

在开发构建的实际组件实例上临时计数 render 调用，逐次修改播放时间和进度，每次等待 Vue 更新，合计 60 次：

| 组件         | 进度变化后的 render 次数 |
| ------------ | ------------------------ |
| PlayerSlider | 60                       |
| AppLayout    | 0                        |
| Nav          | 0                        |
| Sider        | 0                        |
| 推荐首页     | 0                        |
| MainPlayer   | 0                        |

随后改变歌曲标题、播放状态并展开播放器，标题 DOM 正确更新，播放器显示，AppLayout 记录到必要更新。Vue 的 slot 会使部分更新在子组件中执行，不能要求每个父组件都增加计数。没有观察到上述目标组件因无关进度变化重新挂载。

临时计数仅安装在隔离浏览器内，结束后恢复原 render 函数及状态，源码中没有保留调试计数、节流或 `v-memo`。该检查没有证明实际可闻播放、CPU 使用率或电池续航改善。

## 复测

```sh
VITE_API_URL=http://127.0.0.1:14669 \
pnpm exec vite build --config vite.config.ts --manifest
pnpm exec vite preview --config vite.config.ts --port 14668
```

在新的浏览器会话打开 `http://127.0.0.1:14668/`，等待 `.home-page` 后，记录同源脚本地址、正文长度和是否请求 Pixi。随后展开播放器并选择对应歌词／背景效果，确认资源延迟请求且内容出现。后续改动需在相同条件下重新采集，不能直接复用本次体积数字。
