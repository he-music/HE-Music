# 运行资源、播放检查点与曲库优化

本记录对应 `eab3514` 后的本轮工作区，补充 [前端加载与更新测量](frontend-performance.md)。

## 改动

- 流体背景卸载时立即暂停并销毁，移除被卸载钩子取消的延迟销毁任务；背景随播放状态与页面可见性暂停、恢复。
- 播放位置按十秒区间保存检查点，保持毫秒精度及原存储格式。其他设置仍及时保存；暂停、显式跳转、页面隐藏／离开及退出、重载、导出前提交最新位置。关闭记忆位置时不保存进度。
- 正常连续播放期间异常终止，恢复位置可能落后不到十秒的播放进度；正常退出先提交检查点，再等待原生写入。
- 曲库扫描命中元数据缓存时不重复归一化及登记元数据；只有索引发生变化才序列化和写盘，写入失败保留脏标记供后续重试。每次扫描仍重新核验目录授权和文件身份。
- 前端复扫以深度比较复用未变化条目，避免逐条 JSON 序列化。本地歌曲按稳定路径 ID 与旧文件 ID 建立惰性查询索引，目录撤销、原生引用更新和下载发布后随结果重新计算。

## 浏览器检查

Node 24.22.1、pnpm 10.28.1、本地 Vite 开发构建，隔离 Chromium 会话；后端固定为不可用的 `http://127.0.0.1:14669`，只使用合成歌曲和本地静态封面。

- 展开播放器并启用流体背景，实际创建 Canvas。临时计数渲染器方法：播放后暂停记录到一次 `resume`、一次 `pause`；隐藏页面再恢复分别触发暂停、恢复；关闭播放器后累计一次 `dispose`，Canvas 移除。
- 60 次进度更新均等待 Vue 更新，AppLayout、Nav、Sider、MainPlayer 的 render 计数均为 0，背景实例保持一致。播放状态变化仍调用原渲染器暂停、恢复。
- 对实际 Pinia store 每 250ms 模拟一次播放位置更新，推进一分钟：`status-store` 写入 6 次。随后暂停保存 `61555ms`，调用 `flushApplicationWrites()` 保存 `62345ms`。
- 所有计数和模拟可见性只存在于隔离会话，检查后恢复方法与属性；源码无临时调试代码。

这些检查验证界面生命周期和状态写入，不代表真实可闻输出、原生 WebView 行为或 CPU／GPU／续航测量。

## 合成曲库基准

同一 Node 24.22.1 进程，分别生成 1 千、1 万、5 万条包含原生引用和完整展示元数据的条目，使用 `structuredClone` 创建语义相同的新结果。
比较逐条 JSON 序列化与 `lodash-es/isEqual`，各执行七次取中位数。查询固定为靠近列表尾部的 100 个稳定路径 ID，对比原数组查找与已建立的 Map。建索引单独计时，查询计时不包含构建成本。

| 条目数 | JSON 比较 | 深度比较 | 建立查询索引 | 数组查询 100 次 | Map 查询 100 次 |
| ------ | --------- | -------- | ------------ | --------------- | --------------- |
| 1,000  | 2.63ms    | 3.36ms   | 0.44ms       | 17.76ms         | <0.01ms         |
| 10,000 | 24.05ms   | 21.12ms  | 6.63ms       | 220.25ms        | 0.01ms          |
| 50,000 | 122.10ms  | 92.60ms  | 22.59ms      | 800.65ms        | <0.01ms         |

小集合的深度比较没有表现出耗时优势；其确定收益是避免临时 JSON 字符串分配。查询索引额外占用内存，首次查询和曲库变化后需要重建。
以上只测内存算法，不包括磁盘扫描、桥接传输、搜索排序、界面渲染，也不能推导真实曲库整体提速比例。

## 自动验证

- 前端测试覆盖 20 次背景挂载／卸载、页面可见性、播放状态传递、进度检查点和关键落盘边界。
- 1 千、1 万、5 万条合成扫描结果复用原列表且不调用 JSON 序列化；原生引用更新、下载发布和目录撤销后查询结果正确。
- Go 测试确认无变化复扫不替换索引文件，音频变化仍保存索引，失效条目删除可持久化，失败写入保留脏标记并可重试。

本轮通过 212 个 Vitest 文件、1872 条测试，Node／Web 类型检查、ESLint、改动文件格式检查、Go lint、`CGO_ENABLED=0 go test ./...`，以及 Web／桌面前端构建。构建保留现有的分包大小及静态／动态导入混用提示。

复测入口：

```sh
pnpm test
pnpm typecheck
pnpm lint:check
pnpm lint:go
CGO_ENABLED=0 go test ./...
pnpm build:web
pnpm build:desktop:frontend
```

本轮不重复 Windows、Linux、macOS 真机自测；此前平台自测由用户完成。新增变更的三端原生资源消耗和真实大曲库端到端耗时尚未测量。
